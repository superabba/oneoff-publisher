# 일회성 발행 (블로그 + 릴스·스레드·쇼츠 + 클립)

사용자가 주제와 사진을 올리면, 경제주막 네이버 블로그(경제 카테고리)에 글을 발행하고
같은 내용을 인스타 릴스·스레드·유튜브 쇼츠와 경제주막 네이버 클립에 올린다.
영상에는 주제 분위기에 맞춘 배경음악을 합성해 넣는다.
영상은 카드뉴스 스타일이 아니라 큰 글자 + 사진 카드 스타일이다.
**디자인은 항상 사용자가 준 사진의 이미지와 같거나 비슷하게** 만든다 (사용자 요청). 사진의 배경색·강조색·글자 느낌·상품 이미지를
따라 `spec.json`의 `theme`(bg·ink·accent·card)를 정하고, 사진에서 잘라 낸 상품·카드 이미지를 `photo` 블록에 쓴다.
노랑·검정·빨강 기본 테마는 사진에 맞는 색이 없을 때만 쓴다. 한 게시물의 릴스·쇼츠·클립은 같은 영상을 쓴다.

**카드뉴스봇(superabba/my-site)은 쓰지도, 건드리지도 않는다.** 숏폼 게시는 전부
`superabba/oneoff-publisher` 저장소에서 한다. 그래서 카드뉴스봇 이력 DB를 지우는 뒷정리도 필요 없다.

## 고정값

- Uplika 워크스페이스: `ws_3a45040ee5856407` (economypub = 경제주막)
- 네이버 블로그 계정: `conn_4229412d79bc99ce`, 경제 카테고리 `categoryId: "2"`
- 네이버 클립: `conn_efdce3d2f5b04bc8` (handle `economypub`). **경제주막 워크스페이스에 연결된 클립 계정에만** 올린다. `superabba`(슈퍼아빠) 워크스페이스의
  클립('스노우볼23')에는 절대 올리지 않는다. 경제주막 클립이 연결돼 있지 않으면 올리지 말고
  https://uplika.com/dashboard/connections 에서 economypub 워크스페이스에 연결하라고 안내한다.
- 발행 저장소: `superabba/oneoff-publisher` (공개). 코드는 `main`, 게시물·결과는 `data` 브랜치 `posts/<id>/`
- 워크플로: `.github/workflows/publish.yml` (workflow_dispatch, 입력 `post`, `action`, `platforms`)

## 순서

### 0. 시작 전 확인 (한 번에 끝낸다)
- 광고·협찬(대가성)은 **기본적으로 없음**으로 보고 묻지 않는다. 사용자가 대가성이 있다고 말한 경우에만
  블로그 첫머리와 캡션 맨 앞에 "광고"·"협찬" 등 대가 내용을 표기하고, 클립은 `adDisclosure: true`.
- `add_repo`로 `superabba/oneoff-publisher`를 push 권한으로 붙이고 클론한다.
- Uplika `bridge_status`(workspaceId 경제주막)로 네이버 확장(Edge)이 켜져 있는지 본다. 꺼져 있으면 사용자 컴퓨터가
  연결돼 있을 때 `start msedge`로 깨워 보고, 안 되면 "Edge를 켜야 블로그 글이 나간다"고 미리 알린다.

### 1. 사실 정리
- 사진에서 읽은 내용, 사용자가 말한 내용만 사실로 쓴다. 웹에서 공식 페이지를 찾을 수 있으면 확인한다.
- 사진에서 찾지 못한 것(판매가, 물량, 발급 조건 등)은 지어내지 않는다. **블로그 글에는 '확인하지 못한 것'을 따로 적지 않고** 글에서 그냥 뺀다.
  (사용자 요청, 2026-11-02). 확인하지 못한 것은 사용자에게 보고할 때만 알려 준다.
- 직접 계산한 숫자는 "제 계산"이라고 표시한다.

### 2. 사진 준비
- 사진에서 앱 UI·개인정보 부분을 잘라 낸다 (Pillow). 잘라 낸 파일을 `posts/<id>/`에 영문 이름으로 저장.
- **상징적인 이미지(캐릭터·마스코트·상품·카드·행사 키비주얼)가 있으면 반드시 잘라 내서 영상과 블로그에 쓴다** (사용자 요청, 2026-11-02).
  글자만 있는 캡처(조건·유의사항)보다 캐릭터·상품 이미지가 눈에 먼저 들어오므로, 첫 장면(커버)과 마지막 장면에 `photo` 블록으로 크게 넣고,
  블로그 첫 사진과 슬라이드에도 쓴다. 글자 캡처만 있으면 영상은 글자 카드 위주로 만들되, 블로그에는 아래처럼 구간별로 잘라 넣는다.
  사진을 받으면 먼저 상징 이미지가 있는지 보고, 있으면 그 이미지의 색(배경·강조색)을 `theme`에도 반영한다.
- **글자 위주 캡처(도움말·안내 화면)는 구간별로 잘라서 블로그 본문의 해당 위치에 넣고, 통짜 원본은 글 맨 끝에 넣는다** (사용자 요청, 2026-11-05).
  - 원본 파일(드라이브·대화에서 받은 것)을 **원래 해상도 그대로** 연다. 대화창에 올린 사진은 세로가 2,000px로 줄어드니, 아주 긴 캡처는
    구글드라이브에서 받는다 (`search_files`로 찾고 `download_file_content` 결과 파일의 base64를 디코딩).
  - 소제목·단락 경계에서 자른다 (글 한 덩어리가 중간에 잘리지 않게). 가로는 본문 폭만 남기고 좌우 여백을 뺀다 (`crop((x0, y0, x1, y1))`).
    위쪽 고정 바(sticky header)에 글자가 가려진 구간은 피하거나, 원본에서 가려진 그대로 둔다.
  - 잘라 낸 사진은 **PNG(무손실)** 로 저장하고 파일 이름은 `sec_1_xxx.png`처럼 영문으로 쓴다. 자른 뒤에는 경계가 어긋나지 않았는지
    몽타주나 가장자리 크롭으로 눈으로 확인한다.
  - 본문에서는 그 구간을 설명하는 글 **바로 뒤**에 `![설명](media:<id>){.fit}`로 넣는다. 구간 사진 앞에 설명 문구를 따로 쓰지 않는다.
  - 통짜 원본은 규칙 그대로 한 줄 정리 다음 맨 끝에 (재압축 없이, 문서 너비로).
  - 이미 발행한 글에 나중에 추가할 때는 `update_post`에 전체 본문과 `options`를 다시 넘긴다 (같은 주소 유지).
  - Python으로 한글이 든 파일을 고칠 때는 `PYTHONUTF8=1`을 켠다 (윈도 기본 인코딩이면 글자가 깨져 수정이 안 된다).
- **사진을 못 받은 정보성 주제(세금·제도·지급 방법 등)는 코드로 그린 일러스트 3장을 블로그에 넣는다** (사용자 결정, 2026-11-09).
  `python tools/illustrate.py <spec.json> posts/<id>` → `illust_1.png`~`illust_3.png` (1600x900, Pillow로만 그림. 인터넷·API·AI 이미지 생성·비용 없음).
  spec 형식과 아이콘 종류(calendar·document·calculator·coins·phone·card·chart·passbook·check·warning)는 `tools/illustrate.py` 맨 위 설명을 본다. palette(green·blue·orange·purple)는 주제 분위기로 고른다.
  배치: 1번은 도입 바로 뒤, 2번은 글 한가운데(핵심 설명 절 뒤), 3번은 체크리스트 앞이나 뒤. 사진처럼 설명 문구 없이 `![설명](media:<id>){.fit}`.
  **그림 속 글자(제목·부제·label)도 글에 쓰는 사실과 같아야 한다.** 공식 자료로 확인 못 한 숫자·날짜(예: 납부 달, 비율)는 그림에 넣지 않는다.
  브랜드·실제 상품이 있는 주제에는 쓰지 않고 사용자가 주는 공식 이미지를 쓴다. 영상 캡처(`slide_*.jpg`)는 일러스트가 안 맞을 때만 보조로 쓴다.
- **사진 없이 글(주제)만 받았을 때는 주제에 맞는 스타일 하나를 골라 그림 3장 + 영상을 같은 스타일로 만든다** (사용자 결정, 2026-11-10 — 아래 두 항목보다 우선; 이 방식이 안 맞을 때만 `illustrate.py`·영상 캡처로 돌아간다).
  스타일은 lemomo-ai/lemo-opuscar에서 3가지를 골랐다 (엔진 MIT, `tools/vendor/lemo-opuscar/LICENSE`):
  | 주제 | 스타일(`style`) | 쓰는 곳 |
  |---|---|---|
  | 절차·흐름·구조 (신청→계산→납부, 지급 방법) | `iso` 등각 인포그래픽 | 서류·계산기·동전·폰 같은 물건을 놓고 핀으로 이름 |
  | 숫자 하나가 핵심 (한도·%·금액) + 조건 목록 | `swiss` 스위스 모션 | 큰 숫자 + 번호 붙은 조건 줄 |
  | 가볍고 행사·혜택 분위기 (할인·적립·이벤트) | `riso` 리소그래프 | 두 가지 잉크색 망점, 큰 숫자, 아래 띠에 날짜 |
  1. 그림 스펙 JSON을 쓴다 (형식은 `tools/make_pictures.py` 맨 위 설명). 3장: 도입 뒤 / 글 한가운데 / 체크리스트 앞.
     iso는 장마다 물건(`objects` 1~3개)을 바꾸고, swiss·riso는 장마다 강조할 숫자·문구를 바꾼다. **그림 속 글자는 확인된 사실만** (규칙 3).
  2. `PYTHONUTF8=1 python tools/make_pictures.py <스펙.json> posts/<id>` → `illust_1~3.png`(1600x900). 로컬 Chrome으로 그려서 API·비용이 없다. 반드시 눈으로 확인한다 (글자 겹침, 사실 일치).
  3. 영상 spec.json의 `theme`는 출력 끝에 찍히는 값(스타일별 `THEMES`)을 그대로 쓰고, 첫 장면(또는 핵심 장면)에 `illust_1.png`를 `photo` 블록(width 940~980)으로 넣는다.
     그림이 가로(16:9)라 세로 영상에서는 카드처럼 가운데 놓인다. 영상 장면 글자도 같은 배색이 된다.
  4. 블로그: `![설명](media:<id>){.fit}`로 위 위치에 넣는다 (설명 문구 없이).
  Chrome(또는 Edge)이 이 PC에 있어야 하고(`tools/render_iso.py`가 찾는다), 클라우드 세션에서는 `illustrate.py`를 쓴다.
- **사용자가 사진을 주지 않고 글(주제)만 줬을 때도 블로그에는 사진을 넣는다** (사용자 요청, 2026-11-09).
  방법: 먼저 영상을 `render`해서 나온 `slide_01.jpg`~`slide_NN.jpg`(1080x1350, 영상과 같은 디자인)와 `reel_cover.jpg`를 블로그에 쓴다.
  `reel_cover.jpg`(또는 `slide_01.jpg`)를 도입 바로 뒤에, 나머지 슬라이드는 같은 내용을 설명하는 절 뒤에 넣는다 (`![설명](media:<id>){.fit}`, 설명 문구 없이).
  `posts/<id>/`에 이미 있는 파일이라 raw URL로 `media_from_url`에 올리면 된다. 인터넷에서 사진을 검색해 가져오지는 않는다
  (사진마다 저작권·사용 조건이 달라 확인할 수 없고, 글 내용과 맞는지도 보장할 수 없다). 사용자가 특정 사진을 말하면 그 사진을 받아서 쓴다.
- `<id>`는 `YYYYMMDD-영문키워드` (영문·숫자·`-`만; Meta가 한글 URL을 못 읽음).

### 3. 블로그 글 → 네이버 발행
- **말투: 글쓴이가 사진의 내용을 이미 다 알고 독자에게 직접 설명하는 식으로 쓴다** (사용자 요청, 2026-11-04). 해요체, 과장 금지.
  사진이나 화면을 설명하는 말투를 쓰지 않는다. 쓰지 말 것: "안내 화면에 적혀 있어요", "사진을 보면", "~라고 안내돼 있어요",
  "~라고 적혀 있어요", "화면 기준으로", "행사 안내 화면을 기준으로 정리했어요". 사실만 바로 말한다.
  예) ✕ "기간 내 3회, 1회 최대 1개까지라고 안내돼 있어요." → ○ "기간 내 3회, 1회 최대 1개까지 받을 수 있어요."
  예) ✕ "안내에는 연회비가 없다고 적혀 있어요." → ○ "연회비는 없어요."
  사진에서 읽은 사실만 쓰는 규칙(AGENTS.md 3번)은 그대로다. 말투만 바꾸는 것이지 확인 안 된 내용을 단정하라는 뜻이 아니다.
- 구성: 도입 2~3문장 → 사진 → `## 한눈에 보기` 표 → `## 체크 ①②③` → 일상 비유 하나 → `## 가입(참여) 전 체크리스트`
  → `## 한 줄 정리` (인용). '이 글에서 확인하지 못한 것' 절은 넣지 않는다.
  **글 맨 끝(한 줄 정리 다음)에 사용자가 준 사진 원본을 자르지 않은 그대로 전부 다시 넣는다** (사용자 요청, 2026-11-02).
  본문 중간에 쓴 사진도 원본이면 끝에 한 번 더 넣는다. 원본 파일은 `posts/<id>/`에 올려 두고 `media_from_url`로 올려 `![원본 사진](media:<id>)`로 넣는다.
  - 원본은 **다시 저장하지 않고 받은 파일 그대로 복사**한다 (Pillow로 열어 `save`하면 다시 압축돼 화질이 떨어진다). 확장자도 그대로 둔다.
    잘라 낸 사진(영상용 `product.jpg` 등)은 따로 만들고, 블로그 끝 원본은 이 복사본을 쓴다 (`orig_1.jpg`, `orig_2.jpg` …).
  - **끝에 넣는 원본 사진은 문서 너비로** 넣는다 (사용자 요청, 2026-11-04). 사진 줄마다 `![](media:<id>){.fit}`처럼 `{.fit}`을 붙이고,
    `options.naver_blog.imageSize`도 `fit`으로 준다. 사진이 작게 줄어들지 않게 한다.
  - **끝에 붙이는 원본 사진에는 '원본'이라는 표시를 어디에도 넣지 않는다** (사용자 요청, 2026-11-11). 마크다운 대체 텍스트(`![원본 사진](...)`의 괄호 안 글자)도 네이버가 사진 밑에 보여 줄 수 있으니 **비워 둔다**: `![](media:<id>){.fit}`. '원본 1쪽' 같은 이름도 쓰지 않는다.
  - **원본 사진 앞에 설명 문구(예: '화면 원본 전체', '요금제 상세 화면 캡처 원본 전체예요' 같은 안내)를 쓰지 않는다.** 한 줄 정리 바로 다음에 사진만 둔다 (사용자 요청, 2026-11-02).
  - **세로가 4,000px보다 긴 원본은 한 장으로 올리지 않고, 이어지는 PNG 조각으로 나눠서 끝에 넣는다** (사용자 선택, 2026-11-05).
    이유: 네이버는 Uplika 확장으로 올린 긴 JPEG(대략 세로 6,000px 이상)를 높이 1,600px로 줄여 보여 준다 (2,628x20,217px → 208x1,600px, 글자 못 읽음).
    같은 파일을 사용자가 편집기에서 직접 올리면 줄지 않는다 (경로 차이, 원인은 확인 못 함). PNG는 줄지 않지만 2MB를 넘으면 네이버가 JPEG로 바꿔 다시 줄어든다.
    방법: `python tools/slice_original.py <원본> <폴더> --prefix orig_1` (조각당 PNG 1.8MB 안, 화소는 그대로). 나온 `orig_1_01.png`, `orig_1_02.png`…를
    순서대로 `posts/<id>/`에 넣고 Uplika에 올려 한 줄 정리 다음에 **붙여서** 넣는다 (`{.fit}`, 설명 문구 없음). 세로가 4,000px 이하인 원본은 지금처럼 JPEG 그대로.
    올린 뒤 `PostView` 주소(`blog.naver.com/PostView.naver?blogId=economypub&logNo=<번호>`)의 이미지 주소에 `?type=w2000`을 붙여 받아 보면 크기가 줄었는지 확인할 수 있다.
  - 원본 해상도가 낮으면(가로 1,000px 미만) 늘려서 넣지 않고 그대로 넣는다. 더 큰 원본이 필요하면 사용자에게 파일로 다시 받을 수 있는지 묻는다.
- 사진은 data 브랜치에 먼저 push 한 뒤 raw URL(`https://raw.githubusercontent.com/superabba/oneoff-publisher/data/posts/<id>/<file>`)을
  Uplika `media_from_url`(workspaceId 경제주막)로 올리고, 본문에 `![설명](media:<id>)`로 넣는다.
- **일상 비유도 사진·화면에 없는 사실을 단정하지 않는다** (예: 유심·요금 청구 방식을 지어내 비유에 쓰지 않는다). 확실하지 않으면 쿠폰·기한 같은 일반적인 비유를 쓴다.
- **태그·제목·키워드의 한글은 유니코드 코드값(백슬래시 u + 숫자)으로 쓰지 않고 한글 그대로 쓴다.** 코드값을 잘못 적으면 글자가 바뀐다 (실제로 '알뜰폰'이 '알뜩폰'으로 들어간 적이 있다).
  발행 직후 결과의 `options.naver_blog.tags`를 눈으로 다시 읽어 오타를 확인한다.
- Uplika `publish` (workspaceId, `conn_4229412d79bc99ce`, options.naver_blog: title, categoryId "2", tags 10~12개,
  openType public, layout "as-is", seoKeywords), `wait: true`.
- 확장이 꺼져 있어 대기열에 들어가면 **발행됐다고 말하지 않는다.** userMessage를 그대로 전하고,
  나중에 `get_post`로 다시 확인해 링크를 알려 준다.

### 4. 숏폼 원고 (spec.json)
`posts/<id>/spec.json`을 쓴다. 형식은 저장소 README의 'spec.json 형식', 예시는 `examples/joym-5500/spec.json`.
- 장면 5~7개, 장면당 블록 3~5개. 첫 장면 = 가장 센 숫자/질문 (첫 프레임부터 보임).
- 마지막 장면 = 체크리스트 + `"자세한 정리 · 네이버 블로그 '경제주막'"` (accent pill).
- `[ ]` 안 글자는 빨강 강조. 한 장면에 강조는 1~2곳만.
- caption(릴스·쇼츠 설명): 2,200자·해시태그 30개 이하, 실제로는 400~600자·해시태그 10개 안팎.
  "※ 참여 전 공식 안내에서 꼭 확인하세요" 같은 단서 한 줄. (캡션·스레드도 사진을 설명하는 말투는 쓰지 않는다.)
- threads: 500자 이하, 해시태그 1~2개.
- title: 유튜브 제목 100자 이하.
- music: 주제 분위기를 보고 직접 고른다 (README 'spec.json 형식'의 배경음악 표).
  `calm` 잔잔(정보 정리) / `warm` 따뜻(지원금·환급·생활 정보) / `bright` 경쾌(특가·할인·이벤트·혜택) /
  `upbeat` 신나는(선착순·마감 임박) / `tense` 주의(사기·피싱·손해). 사용자가 분위기를 말하면 그대로 따른다.
  비우면 `auto`(원고 단어로 선택). 그 분위기 곡이 `music/library.json`에 있으면 실제 곡을, 없으면 합성 음악을 쓴다.
  사용자가 곡을 지정하면 `music_track`. `check` 출력의 '배경음악'·'출처 표기' 줄로 확인한다.

### 5. 미리보기 확인 (필수)
```bash
cd oneoff-publisher && pip install -r requirements.txt --break-system-packages -q
python -m oneoff check posts/<id> && python -m oneoff preview posts/<id>
```
`posts/<id>/preview_video.jpg`, `preview_slides.jpg`를 Read로 직접 보고, 글자 넘침·겹침·빈 화면을 고친다.
필요하면 `python -m oneoff render posts/<id>`로 영상까지 만들어 0초·장면 중간 프레임을 확인한다.

### 6. 릴스·스레드·쇼츠 발행
- `data` 브랜치에 `posts/<id>/`(spec.json + 사진 + 렌더 결과물)를 커밋·push.
  로컬에서 render 했으면 결과물(reel.mp4 등)도 같이 올린다 → 본 그대로 게시된다.
- 커밋 메시지 끝에 세션이 지정한 Co-Authored-By / Claude-Session 줄을 붙인다.
- `gh workflow run publish.yml --repo superabba/oneoff-publisher -f post=<id> -f action=publish`
- `gh run list --workflow publish.yml --repo superabba/oneoff-publisher -L 1`로 run id를 찾아 `gh run watch <id> --exit-status`
  (백그라운드로 돌리고 끝나면 확인).
- 끝나면 data 브랜치 `posts/<id>/published.json`에서 링크를 읽는다. `errors`가 있으면 그 플랫폼만
  `-f platforms=<실패한 것>`으로 다시 돌린다 (성공한 플랫폼은 자동으로 건너뜀).

### 7. 네이버 클립 (기본으로 같이 올림)
- `list_accounts`(workspaceId 경제주막)에 `platform: naver_clip` 계정이 있는지 확인. 없으면 위 '고정값'대로 안내하고 멈춘다.
- 영상: data 브랜치 `posts/<id>/reel.mp4`의 raw URL을 `media_from_url`(workspaceId 경제주막, aiGenerated false)로 올린다.
- 설명: 스레드 글을 줄여 **설명 + 태그(#) 합계 300자 이하** (UTF-16 길이로 미리 계산). 태그는 최대 5개.
  `posts/<id>/music.json`의 `credit`이 비어 있지 않으면(CC BY 곡) 그 줄을 설명 끝에 **반드시** 넣고 그만큼 본문을 줄인다.
- `publish`: options.naver_clip = categoryId(2단계 id, 특가·할인은 `쇼핑 › 할인정보` 등 계정의 categories에서 선택),
  tags, visibility public, aiGenerated false, adDisclosure false(대가성 없을 때), `wait: true`.
- Uplika는 클립 수정·삭제를 못 한다 → 올린 뒤 고칠 일이 생기면 사용자가 clipcreators.naver.com에서 직접.
  그래서 계정·카테고리·설명을 **올리기 전에** 한 번 더 확인한다.

## 실패했을 때
- 인스타·스레드 토큰 오류(190, OAuthException): my-site의 '일회성 발행기 시크릿 동기화' 워크플로를 실행해
  최신 토큰을 다시 복사한다 (`gh workflow run oneoff-secrets-sync.yml --repo superabba/my-site`).
- 시크릿 복사가 안 되면: 사용자가 CARDBOT_ADMIN_TOKEN(PAT)에 oneoff-publisher 저장소를 추가해야 한다.
- 클라우드 세션에서는 저장소 생성, 시크릿·변수 API, 클립 크리에이터 접속이 막혀 있다. 사용자에게 화면에서 할 일을 안내한다.
